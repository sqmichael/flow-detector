# Memory Layer Research v0.1

> Research synthesis from multi-model review session. Foundation for implementation planning.

**Date:** 2026-02-02
**Models Consulted:** DeepSeek v3.2, Cogito v2.1 671B, Claude Opus 4.5
**Status:** Design finalized, ready for v1 implementation

---

## Original Spec Summary

See: `docs/MEMORY_LAYER_SPEC.md`

**Core Principle:** "Memory should make the agent feel like it was paying attention, not like it's watching you."

**Two-Tier Architecture:**
| Tier | Scope | Decay | Visibility |
|------|-------|-------|------------|
| Session | Current call only | Dies when call ends | Invisible |
| Remembered | Cross-session themes | 4 weeks | Transparent |

**What Gets Remembered:**
- Themes ("the vendor negotiation") — not data ("HRV dropped 23%")
- Topics ("that proposal") — not emotions ("you seemed anxious")
- Preferences ("walks help") — not patterns ("you always get stressed")

## Model Reviews

### DeepSeek v3.2 (Deep Analysis)

**Strengths Identified:**
- "Paying attention vs. Watching" principle is brilliant
- Ripcord is non-negotiable for avoidant user profile
- "Point at the thing, not the user" framing rules are a masterclass
- Two-tier model is clean and explainable

**Critical Gaps:**

| Issue | Problem |
|-------|---------|
| Theme Confirmation UX | Notification after every call feels transactional, will be ignored |
| "Energy" proxy language | User will ask "How do you know my energy?" — feels like obfuscation |
| Local-only storage | What if MacBook dies? Need opt-in encrypted sync eventually |
| "A few times" promotion | Still bean-counter energy — how many is "a few"? |
| 4-week decay | Arbitrary — should be activity-based (4 weeks of inactivity) |

**Contradictions Identified:**
1. Transparency vs. Invisibility — can't be both fully
2. "Secure Base" vs. "No Dependency Creation" — secure base IS healthy dependency
3. "Prove Competence" vs. "No Intelligence Theater" — must show memory sometimes
4. Local Storage vs. Multi-Device Reality — executive uses phone AND laptop

**Key Quote:**
> "The paranoid user needs to feel in control of the ledger, not suspect a hidden one exists."

### Cogito v2.1 (Practical Focus)

**Validation Concern:** Post-call notifications have low engagement rates. Suggest contextual validation during next related interaction instead.

**Suggested Additions:**
- "What do you remember about X?" query option for transparency
- Biometric integration as opt-in, not default
- Encrypted cloud sync as opt-in for device failure (later)

**Recommended v1 Scope:**
1. Two-tier memory with 4-week expiry
2. Simple remember/forget commands
3. Ripcord essential
4. Local storage only

## Synthesis: Recommended Changes

### 1. Kill Post-Call Notifications

**Problem:** Notification after every call = paperwork. Low engagement guaranteed.

**Solution:** In-call confirmation only. At natural conversation end:
> "Was that about the vendor thing, or something else?"

User says "yeah" or "no, it was about Steve" — done. No notification, no UI.

### 2. Activity-Based Decay

**Problem:** 4 weeks absolute time is arbitrary. Slow-cycle topics vanish right before they matter.

**Solution:** 4 weeks since last mention. If vendor thing comes up every 3 weeks, it lives. If dormant, it fades.

### 3. Add "What Do You Remember?" Escape Valve

**Problem:** User needs to audit the ledger without suspecting a hidden one exists.

**Solution:** Voice command "What do you remember about me?" — agent reads back short list. Transforms memory from surveillance to shared notebook.

## v1 Implementation Scope

### In Scope

| Feature | Description |
|---------|-------------|
| Theme storage | SQLite with id, theme, context, last_mentioned, expires, source |
| Preference storage | Permanent user preferences ("walks help") |
| In-call confirmation | "Was that about X?" at conversation end |
| Remember command | "Remember that walks help" → "Got it" |
| Forget command | "Forget what I said about Steve" → "Done" |
| What do you remember? | Audit query, reads back list |
| Activity-based decay | 4 weeks since last mention |
| Ripcord | "Dismiss and forget" — ends call, purges session, 24h cooldown |
| Local SQLite | No cloud sync |

### Out of Scope (v1)

| Feature | Why Defer |
|---------|-----------|
| Prompted promotion | Still feels like bean-counting |
| Post-call notifications | Transactional, will be ignored |
| Encrypted cloud sync | Over-engineering for prototype |
| Weekly digest | Another touchpoint to manage |
| Multi-device sync | Solve after core hypothesis validated |

## Hypothesis to Validate

> **Does memory make callbacks feel natural vs. cold?**

Success metrics:
- User rates "well-timed" higher with memory vs. without
- Callbacks reference themes naturally ("that vendor thing again")
- User uses "what do you remember?" to audit, not to catch surveillance

## Open Questions for Future Versions

1. **Theme extraction accuracy** — How reliably can we identify themes from speech? May need user correction loop.
2. **Energy language** — Is "lower energy than usual" safe, or does it trigger surveillance paranoia?
3. **Multi-device** — When/how to add opt-in encrypted sync?
4. **Promotion mechanics** — If we add "want me to hold onto this longer?", when exactly?
